# WAL recovery release comparison — 2026-09-09

The final checks retain a **6.27% decode median cost** versus the old permissive
WAL decoder: 0.252121 → 0.267925 ms per 4,096-row payload, about 16 microseconds.
This is an explicit correctness tradeoff, not a speedup or a whole-node throughput
regression. Encoding is faster in all five pairs; append timings are noisy.

## Workload and final results

Fixture `wal-v1`: 4,096 rows, 0–384 data bytes per row and varied optional topics.
The binary payload is 1,536,328 bytes, CRC32 `2746319339`; framed WAL size is
1,536,340 bytes. Every process checks exact decoded and recovered rows, and all
versions report the same payload size/checksum. The test uses synthetic log rows,
not chain-validation fixtures.

Five alternating baseline/candidate process pairs, 15 samples per process,
75 samples per revision/path. Encode/decode samples average ten operations and
include dropping their returned vectors. Append samples include file open,
encoding, write, flush and `sync_all`, with truncation outside timing. Read samples
include file open, CRC checking, decoding and materializing rows; result assertion
and drop are outside that timing. Untimed validation warms the paths first.

| Path | Baseline median ms | Candidate median ms | Change | Baseline p95 ms | Candidate p95 ms |
| --- | ---: | ---: | ---: | ---: | ---: |
| Encode | 0.088763 | 0.080188 | -9.66% | 0.101667 | 0.098117 |
| Decode | 0.252121 | 0.267925 | +6.27% | 0.271787 | 0.321475 |
| Synced append | 5.625125 | 5.467750 | -2.80% | 6.376000 | 6.050208 |
| Warm read | 0.599625 | 0.562584 | -6.18% | 0.803834 | 0.711916 |

Median-derived decode throughput is 16.25 → 15.29 million rows/s; append is
0.728 → 0.749 million rows/s. These isolated, short synthetic measurements do not
predict node ingestion throughput. Codec p95 is the p95 of batch averages, not
individual request latency. The 75 samples are clustered within five processes.

Pairwise decode changes were +9.82%, +9.80%, +4.83%, +2.63%, +2.45%: a consistent
cost, with magnitude varying. Pairwise encoding changes were -4.90%, -5.05%,
-10.09%, -15.36%, -13.51%. Exact-size checked reservation also avoids the old
underestimated initial encoding capacity and its growth. Warm reads improved in
all five final pairs, but the initial group below showed mixed results; do not
claim a stable startup speedup. Append pairs ranged from -8.64% to +6.59%; there
is no reliable append speedup claim.

Final median process peak RSS was 12,255,232 → 9,404,416 bytes; maxima were
13,582,336 → 10,960,896 bytes. Allocator/process variability is visible in the raw
records. File size is identical; allocated filesystem blocks, write amplification,
end-to-end commit durability and cold startup were not measured.

## Investigation and retained optimization

The initial implementation added checks and fallible reservations but zero-filled
each row's data allocation before overwriting it via `Cursor::read_exact`.
Its first five-pair group measured decode +18.28% (0.238667 → 0.282292 ms),
encoding -7.00%, append +6.78% and read +2.91%. Initial raw records and executable
hashes are retained separately; none are relabeled as final results.

The first sampling attempt ended before collecting useful stacks. A benchmark
iteration override was then added. With `LOGEX_WAL_CODEC_ITERATIONS=3000`, a
three-second `sample` run captured decode allocation and copy work, including
305 stacks at one `try_reserve_exact` call site and 65 through the row `resize`
site (41 descending through memset or its stub). This is sampled evidence, not
an exact attribution of all regression time. The final decoder keeps its bounds
and fallible reservation, copies the already-validated slice once, and advances
the cursor without the redundant zero-fill. No unsafe initialization was added.

A separate five-pair comparison isolated that change: the fully checked decoder
before versus after the single-copy change. Median decode improved **6.47%**,
0.276896 → 0.258983 ms; each pair improved (-2.02%, -4.68%, -7.37%, -9.60%,
-5.93%). Encoding, unchanged in those two versions, varied around parity (-0.62%
aggregate). This supports retaining the copy change while accepting the remaining
checks' cost. The initial append regression did not repeat in the final group;
its sign and magnitude varied with filesystem timing despite identical frame
bytes and sync policy.

Thirty timed processes total: ten initial, ten final, ten isolated-copy runs.
The profiler run and failed sandbox `time -l` attempt are excluded from timing.
The latter failed because macOS `sysctl kern.clockrate` was denied; measurement
